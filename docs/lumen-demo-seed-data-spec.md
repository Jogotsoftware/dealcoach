# Lumen Demo Seed Data Specification

**Version:** v2 (tenant-isolated architecture)
**Purpose:** Single source of truth for populating a new demo tenant in Lumen with realistic synthetic data for the Sage Head of Sales (Melanie) demo. Joe Pacheco's real tenant is never touched. Chaberton's full record tree is deep-copied from real tenant into the demo tenant at seed time.

**Scope**
- Creates a fresh demo tenant (new `organizations` row) and populates it with a synthetic ~98-user Sage Intacct NA sales org plus ~3,000 synthetic deals.
- Deep-copies Chaberton's complete record tree from Joe's real tenant into the demo tenant as a one-time snapshot.
- Idempotent: re-runnable without duplicating synthetic data; Chaberton can be re-copied independently to refresh state before demo.

**Not in scope**
- Any write to Joe Pacheco's real tenant.
- UI build for Melanie's purpose-built dashboard, inspection, forecast, coaching, and deal-drill surfaces (separate build doc).

---

## 1. Tenant Architecture & Real Data Protection

**Architecture decision:** the demo lives in its own tenant — a brand-new `organizations` row — fully isolated from Joe's real tenant.

**Real tenant: zero writes.** No INSERT, UPDATE, or DELETE against Joe's real tenant. Reads only, and only to identify Chaberton's source records.

**Demo tenant: fully self-contained.** All synthetic profiles, all synthetic deals, and the deep-copied Chaberton tree scope to the demo tenant's `org_id`. RLS isolates the two tenants naturally.

**Demo Joe Pacheco is a NEW profile.** Email `joe.pacheco@sage.demo`, fresh UUID, scoped to demo tenant. Same name as real Joe, technically a different user. Owns the demo-tenant Chaberton plus 17-21 synthetic deals.

**Chaberton deep-copy.** Chaberton and every FK'd record gets copied from Joe's real tenant into the demo tenant at seed time. All UUIDs regenerated. All `org_id` rewritten to demo tenant. `owner_id` rewritten to demo Joe. pgvector embeddings copied as-is.

**State synchronization.** Demo Chaberton diverges from real Chaberton over time if Joe processes new transcripts after seed. Fix: re-run the Chaberton deep-copy phase before demo to refresh. Minutes to execute.

**Synthetic data markers.** Every demo-tenant row carries one of two markers in `metadata` jsonb:
- `metadata->>'seed_origin' = 'demo_synthetic_v1'` — generated by seed script
- `metadata->>'seed_origin' = 'chaberton_copy_v1'` — deep-copied from real tenant

Separation enables independent re-runs. If a target table lacks a `metadata` jsonb column, add it via migration before seeding.

## 6. Deal Supporting Data

### 6.1 Pain points (`deal_pain_points`)

70% of active stage≥discovery, 95% of closed-won, 50% of closed-lost. Segment-specific libraries:
- GB/FS: revenue rec, multi-entity consolidation, manual journal entries, multi-dim reporting, audit prep, QuickBooks→Intacct migrations
- Hospitality: F&B cost tracking, multi-location P&L, departmental reporting, banquet/event billing
- NFP: grant tracking, fund accounting, restricted vs unrestricted, FASB compliance, donor reporting
- Healthcare: cost-center allocation, payer reimbursement reconciliation, compliance
- Software PST: ASC 606, deferred revenue tracking, project profitability
- Strategic NFP: multi-affiliate consolidation, federation-wide reporting

### 6.2 Compelling events vs catalysts

`compelling_events` = consequence-of-inaction (bad thing if prospect doesn't change). 50% active, 80% commit, 25% pipeline. Examples: ERP renewal deadlines, audit committee mandates, post-acquisition consolidation, CFO transitions, PE sponsor standardization.

`business_catalysts` = forces driving change (separate table). 70% of active deals.

### 6.3 Contacts and multi-threading

`contacts` + `deal_team_contacts`. Multi-thread role coverage:
- 25%: all 3 critical roles (mobilizer, economic_buyer, blocker)
- 35%: 2 of 3 (usually missing blocker)
- 25%: 1 role only
- 15%: no roles yet

**Deliberate policy violations:**
- 10% of `commit` deals SINGLE-THREADED (Monday Inspection policy violations)
- 5% of `forecast` deals missing economic_buyer

Role enum on `deal_team_contacts.role`: mobilizer, economic_buyer, blocker, champion, technical_evaluator, end_user.

Contact counts: 1-2 early stage, 3-5 mid, 4-7 late.

### 6.4 Decision criteria

60% of active stage≥discovery, 2-5 criteria each. Examples: multi-entity consolidation, revenue rec automation, SOC2 audit trail, integrations, implementation timeline, 3-yr TCO, vendor stability, support model.

### 6.5 Deal scores

Four types (fit, champion, power, deal_health), range 1-5.

| Rep Tier | Fit | Champion | Power | Deal Health |
|---|---|---|---|---|
| Top | 4.0 | 4.0 | 3.8 | 4.1 |
| Average | 3.3 | 3.0 | 2.8 | 3.2 |
| Under | 2.8 | 2.1 | 2.0 | 2.4 |

Per-deal variance ±0.5 from rep average.

### 6.6 Forecast predictions

Every active commit/forecast/upside deal.

- commit: 0.85-0.95 mostly, ~15% below 0.75 (slip-risk)
- forecast: 0.70-0.85 mostly, ~20% below 0.70 (slip-risk)
- upside: 0.40-0.65 mostly, ~15% above 0.80 (pull-in)
- pipeline: 0.20-0.45 mostly, ~5% above 0.70 (pull-in)

Confidence drivers in `signals` jsonb: multi-thread coverage (+), compelling event (+), next meeting within 14 days (+), stale activity (-), single-threaded commit (-), close date pushed (-), competitor named (mixed). Store `feature_snapshot` jsonb.

## 13. Chaberton Deep-Copy

**One-time copy from Joe's real tenant into demo tenant at seed time.** Re-runnable independently if Joe wants to refresh demo Chaberton to reflect new transcript processing.

### 13.1 Source identification

In Joe's real tenant:

```sql
SELECT id, name, owner_id, org_id 
FROM deals 
WHERE owner_id = '<joe-pacheco-real-profile-id>' 
  AND (name ILIKE '%chaberton%' OR company_name ILIKE '%chaberton%');
```

Must return exactly 1 row. If 0 or >1, halt.

### 13.2 Tables to copy (FK dependency order)

Parents → children:

1. `company_profile` (Chaberton's company row)
2. `deals` (Chaberton itself)
3. `deal_analysis`
4. `contacts` (linked to Chaberton's company or deal)
5. `deal_team_contacts`
6. `deal_pain_points`
7. `compelling_events`
8. `business_catalysts`
9. `deal_decision_criteria`
10. `deal_scores`
11. `deal_forecast_predictions`
12. `deal_history_snapshots`
13. `deal_engagement_snapshots`
14. `conversations` (preserve `processed = true` and `ai_summary`)
15. `call_analyses`
16. `transcript_sources`
17. `deal_chat_sessions`
18. `deal_chat_messages`
19. `ai_memory`
20. `ai_corrections`
21. `deal_context_chunks` (preserve pgvector embeddings exactly)
22. `tasks`
23. `next_steps_history`
24. `deal_sources`
25. `deal_competitors`
26. `deal_flags`
27. `deal_risks`
28. `deal_sizing`
29. `company_systems` (linked to Chaberton's company)
30. `company_news`

**Skip:** `ai_response_log`, `ai_suggestion_tracking`, `edge_function_idempotency` — operational, not artifact.

### 13.3 UUID mapping

Maintain session-local map `{real_id → new_id}`. Use to rewire FKs in dependent tables.

Per row:
1. `new.id = newId(row.id)`
2. `new.<fk_columns> = newId(row.<fk_column>)`
3. `new.org_id = demoTenantOrgId`
4. `new.owner_id = demoJoeProfileId` (where applicable)
5. `new.metadata = {...row.metadata, seed_origin: 'chaberton_copy_v1'}`

### 13.4 Verification after copy

Per table, counts must match between real-tenant source and demo-tenant destination:

```sql
SELECT COUNT(*) FROM <table> WHERE <chaberton-FK-or-id-match>;
```

Halt if any table count differs.

Spot-check `deal_context_chunks`: vector dimensions match (1536), 2-3 random rows have matching content.

### 13.5 Re-copy procedure

To refresh demo Chaberton:

```sql
-- Drop existing demo Chaberton tree (reverse FK order)
DELETE FROM deal_context_chunks WHERE metadata->>'seed_origin' = 'chaberton_copy_v1';
DELETE FROM ai_memory WHERE metadata->>'seed_origin' = 'chaberton_copy_v1';
-- ... continue ...
DELETE FROM deals WHERE metadata->>'seed_origin' = 'chaberton_copy_v1';
DELETE FROM company_profile WHERE metadata->>'seed_origin' = 'chaberton_copy_v1';

-- Re-run copy phase
```

Confirm with Joe before destructive re-copy.

## 16. Post-Seed Verification

All queries scoped to demo tenant. Replace `<demo-tenant-id>` with actual UUID.

```sql
-- Demo tenant exists
SELECT id, name, fiscal_year_start_month, metadata 
FROM organizations WHERE id = '<demo-tenant-id>';

-- Profile count by role
SELECT role_level, COUNT(*) FROM profiles 
WHERE org_id = '<demo-tenant-id>'
GROUP BY role_level ORDER BY role_level;
-- Expected: head_of_sales=1, avp=4, rvp=14, ae=79

-- Total deal count
SELECT COUNT(*) FROM deals WHERE org_id = '<demo-tenant-id>';
-- Expected: ~2800-3500 (synthetic + 1 Chaberton)

-- Chaberton deep-copy presence
SELECT id, name, metadata->>'seed_origin' AS source
FROM deals 
WHERE org_id = '<demo-tenant-id>' 
  AND metadata->>'seed_origin' = 'chaberton_copy_v1';
-- Expected: 1 row

-- Chaberton FK tree integrity
SELECT 
  (SELECT COUNT(*) FROM contacts WHERE metadata->>'seed_origin' = 'chaberton_copy_v1') AS contacts,
  (SELECT COUNT(*) FROM deal_pain_points WHERE metadata->>'seed_origin' = 'chaberton_copy_v1') AS pain_points,
  (SELECT COUNT(*) FROM conversations WHERE metadata->>'seed_origin' = 'chaberton_copy_v1') AS conversations,
  (SELECT COUNT(*) FROM deal_context_chunks WHERE metadata->>'seed_origin' = 'chaberton_copy_v1') AS embeddings;
-- All counts must match source Chaberton counts in real tenant

-- Slip-risk count
SELECT COUNT(*) FROM deal_forecast_predictions p
JOIN deals d ON d.id = p.deal_id
WHERE d.org_id = '<demo-tenant-id>'
  AND d.forecast_category IN ('commit', 'forecast')
  AND p.confidence < CASE d.forecast_category WHEN 'commit' THEN 0.90 ELSE 0.80 END
  AND d.stage NOT IN ('closed_won', 'closed_lost', 'disqualified');
-- Expected: 80-120

-- Pull-in candidates
SELECT COUNT(*) FROM deal_forecast_predictions p
JOIN deals d ON d.id = p.deal_id
WHERE d.org_id = '<demo-tenant-id>'
```
